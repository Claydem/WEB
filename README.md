# Якобі

Вебзастосунок для розв’язування великих систем лінійних рівнянь методом Якобі. Потрібен Node.js 24 або новіший.

## Запуск

```sh
npm start
```

Відкрийте [http://127.0.0.1:3000](http://127.0.0.1:3000), створіть обліковий запис і запустіть задачу. SQLite зберігається у файлі `data/tasks.sqlite`. Порт можна змінити через `PORT`, а папку бази — через `DATA_DIR`.

## Як працює

1. Браузер надсилає параметри в `server.js`. Сервер перевіряє сесію, розмір задачі й ліміти та записує задачу в SQLite.
2. Балансувальник у `queue.js` і `workers.js` вибирає вільний сервер обчислень. Якщо вільних кілька, бере той, що найдовше не отримував задачу.
3. Кожний `worker.js` працює в окремому процесі Node.js, слухає власний локальний HTTP-порт і виконує одну задачу за раз. Worker відправляє етапи обчислення та розв’язок назад. Браузер запитує оновлений стан приблизно раз на секунду.
4. Якщо всі сервери зайняті, задачі чекають за порядком надходження. Орієнтовний час очікування враховує середню тривалість останніх задач. Додаткові сервери запускаються автоматично й зупиняються після 30 с простою. Одночасно працює від 2 до 4 серверів обчислень.

Система рівнянь генерується за розміром. На діагоналі матриці стоять одиниці, а сума модулів інших коефіцієнтів рядка дорівнює 0,994. Це забезпечує збіжність методу. Права частина побудована для контрольного розв’язку `1,0; 1,1; 1,2; …; 1,9; 1,0; …`. На кожній ітерації всі нові значення обчислюються з попереднього наближення. Зупинка настає, коли оцінка похибки досягає обраної точності.

Обмеження: 20–1200 невідомих, 12 000 ітерацій, 30 с обчислення, до 3 незавершених задач на користувача, до 10 незавершених задач загалом і до 30 записів історії на користувача.

## Демонстрація балансування

1. Увійдіть у два облікові записи в різних профілях браузера. В одному з них можна використати адміністратора.
2. Виберіть 1200 невідомих і точність 10⁻⁸. Швидко запустіть по три задачі з кожного облікового запису.
3. У списках видно назви серверів, відсотки обчислення й час очікування задач у черзі. Скасуйте одну з задач і відкрийте результат завершеної.
4. У моніторингу видно, як застосунок запускає додаткові процеси під навантаженням і повертається до двох процесів після простою.

## Адміністратор

Перед запуском задайте `ADMIN_PASSWORD` зі своїм паролем (8–128 символів). Наприклад, у PowerShell:

```powershell
$env:ADMIN_PASSWORD = Read-Host 'Пароль адміністратора'
npm start
```

Увійдіть як `admin` і натисніть **Моніторинг**. Панель показує PID, стан задач, завантаження CPU й пам’ять кожного процесу. Якщо запустити застосунок зі змінною `ADMIN_PASSWORD` повторно, пароль адміністратора оновиться.

## HTTPS

Для локальної демонстрації створіть сертифікат і ключ. У PowerShell з Git for Windows:

```powershell
New-Item -ItemType Directory -Force certs
& 'C:\Program Files\Git\usr\bin\openssl.exe' req -x509 -newkey rsa:2048 -sha256 -days 30 -noenc -keyout certs/key.pem -out certs/cert.pem -subj '/CN=localhost' -addext 'subjectAltName=DNS:localhost,IP:127.0.0.1'
$env:TLS_CERT = 'certs/cert.pem'
$env:TLS_KEY = 'certs/key.pem'
npm start
```

Відкрийте [https://127.0.0.1:3000](https://127.0.0.1:3000). Браузер попереджатиме про недовірений локальний сертифікат. Для довіреного сертифіката вкажіть шляхи до його файлів у тих самих змінних. У режимі HTTPS сесійна cookie має атрибут `Secure`.
